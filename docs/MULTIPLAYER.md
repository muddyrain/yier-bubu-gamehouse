# 微信好友房与联机技术预案

> DOC-ONLINE · v1.0 · 2026-10-26 · **P5 计划功能**，所有网络和房间能力均未实现。

## 1. 用户完整路径

`大厅 → 好友一起玩 → 选择支持双人的小游戏 → 创建 2 人房 → 点击微信分享邀请 → 好友点击卡片带参数进入 → 加入房间 → 一二/布布互斥选角 → 双方准备 → 房主开局 → 游戏同步 → 结算 → 再来一局/换游戏/离开`。

为降低门槛：首次只支持 **2 人私人房**，默认同房一二和布布一人一只；先实现合作，再扩展适合对战的玩法。好友主动分享邀请，不尝试未经授权抓取微信好友列表。

## 2. 房间状态机（目标）

```text
CREATED → WAITING → READY → IN_GAME → SETTLEMENT → READY / CLOSED
             ↘ EXPIRED
IN_GAME → RECONNECTING → IN_GAME / SETTLEMENT / CLOSED
```

服务端校验：房间容量、有效期、角色唯一性、房主转移、准备状态、重复请求、断开后超时；房主不能因为好友重新进入就重复开局。

## 3. 微信分享与身份

- 分享仅作为**邀请入口**，携带一次性/短时有效房间邀请参数；后台验证身份与邀请是否有效，不能只相信客户端传入的 `roomId`。
- 微信分享操作由用户主动触发，不做骚扰式自动邀请；好友进入后还需显式加入房间。
- 使用微信登录获得临时登录凭据，再由服务器完成身份校验；客户端和日志不暴露 `session_key`/私密 token。
- 分享字段、微信 API 细节、审核规则在 P5 对照最新官方文档与真机行为验收。

## 4. 联机同步策略

| 游戏 | 后续可行模式 | 同步粒度 |
| --- | --- | --- |
| 黄金矿工 | 双人协作、每人控制抓钩 | 输入/钩子状态、目标归属、双方得分、倒计时由服务端校验 |
| 守护小屋 | 双人协作塔防 | 防御放置意图、资源消费、波次/敌人状态统一裁决 |
| 贪吃蛇 | 双人竞速或对战 | 固定 Tick 下的方向输入与权威碰撞结果 |
| 合成乐园 | 好友竞分优先 | 各自单机逻辑与服务器统一时限、排行榜校验 |
| 双人冒险 | 后续立项 | 高频移动/预测/插值/延迟专项评估 |

实时通信拟使用 WSS，房间关键状态以服务端为权威；不要由客户端直接发“我赢了，给我奖励”。

## 5. 重连、延迟与安全

- 场景切换/前后台时保留最小 `sessionId`，服务端保存可重连快照；合理 TTL 在 P5 真机压测后确定。
- 断线期间可短暂停顿或临时托管，须由游戏分别定义；重复结算应保证幂等。
- 输入频率限制、邀请过期、非法房间状态转移、消息长度限制、版本兼容、防重复奖励属于首版联机必测。
- 保存昵称/头像等个人数据需要单独最小化与隐私审核；不要把账号 ID 写到可公开的分享文案里。

## 6. P1 现在只预留什么

- 能区分 `solo / coop / versus` 的模式枚举。
- 稳定的角色 ID、游戏 ID、单次会话上下文；公共存档不可依赖在线服务。
- 大厅和小游戏之间不要直接互调具体网络 SDK。
- **不**搭建假服务器，不编造当前已能创建/分享房间；P5 到来再依据黄金矿工原型确定真实协议。

## 7. 联机验收（P5）

两台不同真实手机和微信账号：邀请、入房、冲突选角、准备、同时开始、掉线重连、重复结算、防作弊、退出换游戏均有证据。Windows 可做 GUI 联调；macOS 仅允许经审阅的纯后端逻辑单测。
