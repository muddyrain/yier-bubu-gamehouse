# FEAT-004 — 玩家档案、游戏进度和存档

> FEAT-004 · v1.0 · 2026-10-26 · 所属阶段：P1 · 负责人：待定。**实施状态以 `docs/FEATURES.md` 为准，当前为计划方案。**

## 1. 目标与用户故事

作为反复玩不同小游戏的玩家，我希望退出再进仍保存上次进度与个人最佳成绩。

## 2. 玩法 / 交互与状态

- 共享玩家档案与各游戏专属存档分离。
- 关卡结算或安全检查点写盘，失败时不破坏已有有效存档。
- schemaVersion 控制新增字段与迁移，错误数据有安全降级方式。
- 联机开发之前，单机进度完全不依赖服务器。

## 3. 范围与非范围

**包含：**

- SaveRepository 契约与本地实现
- 版本迁移/默认值
- 相关逻辑单测

**不包含：**

- P1 直接上线云存档
- 保存引擎节点、微信会话密钥或任意对象图

## 4. 数据与依赖

- schemaVersion、playerProfile、progressByGameId、sharedRewards
- 数据校验与迁移函数

## 5. 验收标准

- [ ] **AC-01**：两个游戏分别保存的记录互不覆盖。
- [ ] **AC-02**：重开应用后能恢复上次已确认的进度与角色偏好。
- [ ] **AC-03**：模拟旧版本/缺字段/损坏数据时给出可控恢复，不清空整份有效档案。
- [ ] **AC-04**：敏感登录凭据不以明文随游戏存档落地。

## 6. 验证方法

| 环境 | 具体验证 | 目前状态 |
| --- | --- | --- |
| macOS CLI（需事先审核无 GUI） | 存档序列化/迁移/异常注入纯单元测试 | `not_run` |
| Windows GUI | 退出和重启游戏，验证实际持久化 | `not_run` |
| 微信真机（需要时） | 微信真机冷启动后恢复检查 | `not_run` |

**Mac 禁止擅自启动 Cocos、浏览器、微信开发者工具或 GUI 调试。** 未验证部分始终记 `not_run` 或 `blocked`，不能因写完本 Feature 就标通过。
