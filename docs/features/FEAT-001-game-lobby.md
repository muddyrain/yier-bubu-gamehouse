# FEAT-001 — 游戏大厅与目录

> FEAT-001 · v1.14 · 2026-10-30 · 所属阶段：P1 · 负责人：待定。**实施状态只在 `docs/FEATURES.md` 维护。** P1-02 专项已验收；P1-03 的 F-02 已补真实键盘证据；P1-04 已补真实测试模块往返 AC-03；正式四款仍开发中。

## 1. 目标与用户故事

作为首次打开游戏的玩家，我希望直观看到一二与布布、选择游戏并能从任何游戏返回大厅。

## 2. 玩法 / 交互与状态

- 大厅同时展示一二（白熊）和布布（棕熊），不存在默认只有布布的主视觉。
- 按 [ADR-0003](../decisions/ADR-0003-landscape-first.md) 采用 1280×720 横屏设计基准，双角色与目录布局须覆盖不同宽高比和安全区；不在切换游戏时旋转。
- 游戏目录显示四款首发游戏；未开发的入口清楚标注“开发中”，不能点击后报错。
- P1-02 四款均为 `coming-soon`：tower-defense / 一二布布守护小屋、gold-miner / 一二布布黄金矿工、merge / 一二布布合成乐园、snake / 一二布布贪吃蛇；显示名与稳定 ID 分离。点击只显示介绍及“开发中”，不加载不存在的游戏。
- 独立 `Lobby.scene` 使用同规格白/棕程序几何头像、名称和双主角区域。Startup/SmokeTest 继续作为 P1-01 回归入口，不承载正式大厅 UI。
- 大厅只允许一个提示面板：游戏介绍、帮助、当前设置说明、好友预告；关闭或 Escape 返回原大厅。重复打开复用同一节点，不为每次打开新增事件订阅。无存档时不显示继续按钮，明确说明暂无可继续的存档。
- 好友入口标注“敬请期待”，不触发房间、微信登录、分享或选角。设置只说明当前无音效/音乐及可调整项，不制作假开关。
- 进入某款游戏前进入统一选角/模式步骤，完成或退出后回到大厅。
- P1-03 新增独立「选择角色」入口（确认后显示角色姓名及更改），见 FEAT-002。复用一个遮罩，提示与选角内容互斥，原七入口的键盘顺序保持，新入口追加在其后。确认不触发小游戏，游戏卡仍只显示开发中介绍。
- 后台切回或再次启动时恢复合理的大厅状态，不重复创建游戏实例。

## 3. 范围与非范围

**包含：**

- 大厅入口、游戏卡、继续游戏、设置、功能占位说明、退出导航
- 首发阶段可用简单 UI，不要求完整 3D 小屋
- P1-02 为独立大厅、四卡目录、双主角展示和可逆提示；数据/导航纯逻辑与引擎视图分开。后续真实选角/游戏加载在对应 Feature 接入，不提前设置 implemented 或制造局内会话。

**不包含：**

- 自动匹配陌生人
- 在 P1 中实现所有小屋装修动画
- P1-01 的 `Startup.scene` 仅作工程启动测试，不是本 Feature 的正式大厅；双角色矩形占位不等于完成目录、选角或返回流程。
- P1-02 当时不实现 FEAT-002；后续 P1-03 仅实现本地选角。FEAT-003 场景往返、存档、可玩小游戏或联机仍未实现。下面 AC-03 继续留待 FEAT-003 集成，不以面板返回替代。

## 4. 数据与依赖

- GameId / GameCatalogEntry
- GameModuleRegistry 接口由 FEAT-003 定义
- 角色选择依赖 FEAT-002
- LobbyModel 提供只读目录/角色身份、导航与本地选角状态转换；LobbyView 持有 UI 节点、订阅及实例内确认值，通过只读 getter 接入 FEAT-003 开发测试。P1-04 已有实际注册/局部会话/模块源码，RoomService 仍未实现；真实双角色往返已验收，见下方最新证据。

P1-04 新增独立开发测试入口，原七入口/选角仍保留；测试模块活动时大厅隐藏并拒绝自身输入，退出恢复相同实例。上文的 P1-02/03 边界保留为历史；新增注册/会话和实际操作模块源码见 [本轮报告](../reports/2026-10-29_issue-4_game-lifecycle.md)。2026-10-30 已真实完成三比例、双方各三次往返、组件恢复及两次编辑器预览启停，支持 AC-03，见 [演示报告](../reports/2026-10-30_issue-4_visible-demo.md)。测试模块无音频；不宣称正式游戏或长期泄漏完成。
