# FEAT-003 — 小游戏注册与生命周期

> FEAT-003 · v1.1 · 2026-10-28 · 所属阶段：P1 · 负责人：待定。**实施状态以 `docs/FEATURES.md` 为准，当前为计划方案。** P1-03 仅提供未来可读的本地选角结果，不实现本 Feature。

## 1. 目标与用户故事

作为从大厅切换多款游戏的玩家，我希望稳定进入、退出和重复游玩，不因为小游戏互相干扰。

## 2. 玩法 / 交互与状态

- 使用稳定 GameId 将游戏注册到目录和生命周期管理器。
- 游戏加载资源后进入 session；暂停/恢复/退出/销毁有明确顺序。
- 离开游戏释放事件订阅、物理/计时/音效及动态资源。
- 不支持模式要提示，不自动连接网络。

## 3. 范围与非范围

**包含：**

- 注册清单、模块接口、加载/卸载/导航、测试占位场景
- 为 coop/versus 枚举留扩展位

**不包含：**

- 第一阶段为所有未来游戏创建空模块
- 在 P1 启动真实 WSS 服务

## 4. 数据与依赖

- GameId、GameMode、GameSession
- GameModule 生命周期
- GameModule 自己拥有局内状态
- 接入前置：P1-03 的 `LobbyView.getConfirmedCharacter(): CharacterChoice | null`，结果只含稳定 `characterId`，尚未选/确认则 null。未来加载方读取后构造自身会话，不将该偏好视为已有 GameSession 或存档。
- FEAT-002 AC-02 须在本 Feature 有真实可用原型后，分别以一二/布布进入同一场景验收；本轮不提前勾选。

## 5. 验收标准

- [ ] **AC-01**：注册游戏可进入并正确返回大厅至少 3 次，无重复实例。
- [ ] **AC-02**：重复暂停/恢复/退出不导致未捕获异常。
- [ ] **AC-03**：未注册 GameId 会安全报错/提示，不生成空白死界面。
- [ ] **AC-04**：不同游戏的得分/暂存状态不会互相污染。
