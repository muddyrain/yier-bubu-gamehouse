# FEAT-003 — 小游戏注册与生命周期

> FEAT-003 · v1.6 · 2026-10-30 · 所属阶段：P1 · 负责人：待定。**实施状态只在 `docs/FEATURES.md` 维护。** P1-04 已完成真实演示验收；跨正式游戏隔离/获权图像替换仍未执行。

## 1. 目标与用户故事

作为从大厅切换多款游戏的玩家，我希望稳定进入、退出和重复游玩，不因为小游戏互相干扰。

## 2. 玩法 / 交互与状态

- 使用稳定 GameId 将游戏注册到目录和生命周期管理器。
- 游戏加载资源后进入 session；暂停/恢复/退出/销毁有明确顺序。
- 离开游戏释放事件订阅、物理/计时/音效及动态资源。
- 不支持模式要提示，不自动连接网络。
- 首个后续纵切优先「大厅确认角色 → 同一真实测试场景 → 返回大厅」，双方均可进入，清楚标为生命周期测试；四款正式小游戏继续开发中，不用提示面板返回冒充场景往返。
- 原型可复用既有开发占位，不以正式发布授权阻塞功能；正式美术接入仍保持黄小B真实形象目标，未获许可图片不随游戏分发或公开入库。

## 3. 范围与非范围

### P1-04 当前实现边界

- 稳定 development-counter ID 只注册 solo；四款正式游戏保持 coming-soon。Lobby 确认 yier/bubu 后复制到冻结 session，未确认/非法角色/ID/mode 拒绝启动。
- 同一 Canvas 下独立玩法模块，不重建/切换序列化 Scene；目标可点击/键盘计数并移动，暂停冻结计数，继续/退出可键盘导航，退出恢复同一 Lobby。计数每局新建；无存档/奖励/网络。
- GameFlow 单活动 owner：load → enter → pause/resume → exit → dispose；取消加载和迟到完成不会复活旧局。重复操作幂等，清理异常禁止再开新模块并提示重新预览。
- 模块拥有自建节点与输入/尺寸订阅，exit 立即解除/隐藏，dispose 请求销毁，由引擎延迟销毁时脱离父节点，避免父节点停用时的真实层级错误；Lobby 禁用/销毁关闭它。共享角色视觉创建接口复用原几何，不接入未许可图片。
- 不同测试 ID 的纯逻辑夹具通过不等于跨正式游戏实测；AC-04/06 保留未完成。真实双角色/三比例/双方各三次往返/组件恢复及修复导入后两次启停见 [演示报告](../reports/2026-10-30_issue-4_visible-demo.md)。

**包含：**

- 注册清单、模块接口、加载/卸载/导航、测试占位场景
- 为 coop/versus 枚举留扩展位

**不包含：**

- 第一阶段为所有未来游戏创建空模块
- 在 P1 启动真实 WSS 服务

## 4. 数据与依赖

- GameId、GameMode、GameSession
- GameModule 生命周期
- GameModule 自己拥有局内状态
- F-01 加载资源契约：异步 load 每次取得资源（包括每个 await 之后）必须立即调用 `cancellation.retain(() => 释放该具体资源)`，不得先存储、使用或跨越下一次 await。返回 true 才能使用；返回 false 表示本次已取消且已尝试立即释放，必须停止使用。登记的资源由该次加载作用域独占回收，模块 exit/dispose 不重复释放同一资源；同步模块自有节点仍按原 exit/dispose 清理。取消先封闭该作用域，退出时回收已登记资源；迟到登记即时回收，resolve/reject 均不影响新会话。释放函数只捕获所属资源，禁止读取“当前模块/会话”来释放新资源；释放异常记录原错，不能宣称已成功回收。协议不自动回收未登记资源，也不强制终止 Promise 或实现 Asset Bundle 加载。
- 接入前置：P1-03 的 `LobbyView.getConfirmedCharacter(): CharacterChoice | null`，结果只含稳定 `characterId`，尚未选/确认则 null。P1-04 加载方读取后构造新会话，不将该偏好视为已有 GameSession 或存档。
- FEAT-002 AC-02 已由本次真实可用原型的双角色进入/操作/返回验收支持。
- 视觉依赖通过后续可替换解析接口按 yier/bubu 及用途取得，所有角色显示统一接入；模型与会话不绑定原始图文件。完整图像/动画接口仍未实现；P1-04 先将原几何抽为共用创建接口，身份与规则不绑定像素。

## 5. 验收标准

- [x] **AC-01**：注册游戏可进入并正确返回大厅至少 3 次，无重复实例。
- [x] **AC-02**：重复暂停/恢复/退出不导致未捕获异常。
- [x] **AC-03**：未注册 GameId 会安全报错/提示，不生成空白死界面。
- [ ] **AC-04**：不同游戏的得分/暂存状态不会互相污染。
- [x] **AC-05**：确认 yier/bubu 后分别进入同一真实测试场景并返回；未确认/非法 ID 可恢复，不静默选择布布，四款正式游戏状态仍准确。
- [ ] **AC-06**：大厅、选角与测试场景的角色视觉均经过可替换资源边界；替换已获许可的对应资源不改角色 ID、选角结果和生命周期语义，缺资源有明确回退。
