# FEAT-011 — 好友创建房间、邀请、选角与联机

> FEAT-011 · v1.1 · 2026-10-26 · 所属阶段：P5 · 负责人：待定。**实施状态以 `docs/FEATURES.md` 为准，当前为计划方案。**

## 1. 目标与用户故事

作为通过微信邀请来的两名好友，我希望在同一个房间里分别选择一二和布布，一起完成小游戏。

## 2. 玩法 / 交互与状态

- 房主在大厅选择双人游戏，创建 2 人私人房间。
- 房间、选角与开局保持 [ADR-0003](../decisions/ADR-0003-landscape-first.md) 的横屏方向，以同规格区域展示双方信息；不以某只熊为唯一默认主角，不为切入游戏旋转屏幕。
- 玩家主动通过微信分享带短时有效邀请参数的卡片；好友进入后主动加入房间。
- 选角互斥、双方准备、房主开始、游戏同步、掉线恢复、结算及“再来一局/换游戏”。
- 首个实装模式为黄金矿工双人协作，之后扩展塔防合作与贪吃蛇对战。

## 3. 范围与非范围

**包含：**

- 后端房间权威状态、角色选择/准备/转移、邀请鉴权、WSS、重连、结算幂等
- P5 首期只支持 2 人

**不包含：**

- P5 任意好友通讯录读取
- 一开始实现四人房/实时语音
- 第一期就做横版高频联机

## 4. 数据与依赖

- RoomId、InviteToken、SessionId、ServerRoomState、PlayerSlot
- 协议版本、消息鉴权、结算事件幂等键

## 5. 验收标准

- [ ] **AC-01**：两个真实账号能通过微信分享进入同一未满房间。
- [ ] **AC-02**：双方不能同时占据同一角色，交换角色有明确逻辑。
- [ ] **AC-03**：只有双方准备好且房间状态合法才能开始。
- [ ] **AC-04**：短暂断线后安全重连，重复请求不产生多份奖励。
- [ ] **AC-05**：黄金矿工同时抓同一目标按服务端结果唯一结算。
- [ ] **AC-06**：完成一局后可保持房间再玩一局，或按定义切换支持的游戏。

## 6. 验证方法

| 环境 | 具体验证 | 目前状态 |
