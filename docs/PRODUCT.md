# 产品定义（PRD 基线）

> DOC-PRODUCT · v1.2 · 2026-10-30 · 状态：横屏与单关优先方向已由产品确认，其余待确定事项见第 8 节。由此文件定义产品边界，不记录任务执行进度。

## 1. 产品定位

《一二布布游戏屋》是一个可长期扩展的微信小游戏合集，包含具有深度的精品主游戏与数款可反复游玩的轻量经典玩法，通过共享角色、主题、美术、记录、成就与轻量小屋形成共同世界。

**目标体验**：快速开始一局；想玩深入内容时可连续闯关；未来可创建房间邀请微信好友，互选一二与布布合作或对战。避免为了拉长时长强制观看广告、加入无意义体力限制。

**屏幕方向**：全项目首发统一 Landscape 横屏，设计基准 1280×720（16:9），覆盖大厅、选角、四款首发游戏、公共界面和未来双人房，暂不做单游戏动态旋转。合成等窄高玩法在横屏中使用独立场地与两侧 UI；具体布局随对应 Feature 验证。设计基准不等于物理分辨率或已完成安全区/触控适配，详见 [ADR-0003](decisions/ADR-0003-landscape-first.md)。

## 2. 角色与世界观（必须保持）

- **一二：小白熊；布布：小棕熊。两者是平等双主角。** 所有品牌主视觉、主菜单和故事优先同时呈现两个角色。
- 单人可自由选择扮演其中一只；另一个可作为 NPC、背景伙伴或在特定模式被切换控制，具体见 Feature。
- 双人房间中每人选择一只，默认同一房间角色互斥；支持交换/重新选择。若未来模式需要镜像角色，另作设计决策。
- 角色能力差异是**待验证的游戏原创设计**，不是对原作角色性格的确定描述；必须保证单人模式可通关。

## 3. 游戏清单与可玩性原则

- 精品主游戏：《一二布布守护小屋》，原创塔防关卡和策略成长。首发目标 24 关；**先做一张完整森林小屋地图和一个可完成关卡**，两种防御、两种敌人、三波进攻，具备攻击、生命、胜负、重试及统一高品质 2D UI/操作反馈，再扩到五关样板。正式一二布布以原作者形象为标准，未获可用原稿/许可前不将自行设计的相似熊作为最终正式角色。
- 经典游戏：《一二布布黄金矿工》，首发目标 30 关，第一样板 10 关；后续首个好友双人验证对象。
- 经典游戏：《一二布布合成乐园》，合成链、无尽和每日挑战，不要求刷数值。
- 经典游戏：《一二布布贪吃蛇》，清晰手感、机关地图、个人最佳，后续 2 人对战。
- 长期规划：《一二布布双人冒险》、弹射、赛车等，仅在前述游戏验证后再进入立项。

**每款都必须有**：秒级进入/退出、规则说明、暂停或适当替代、结算、重玩理由、双主角一致的美术与回大厅；不能把单局短等同于生命周期短。

## 4. 首发边界

**包含**：游戏大厅、角色选择、模块切换、单机保存、四款游戏的首发内容、基础成就/饼干币、输入适配、异常退出恢复、微信小游戏构建与真机质量验证。

**不包含**：在线好友房、实时 PVP、实体商业支付、复杂社交关系链、完整 3D 场景和《双人冒险》。这些属于后续阶段，接口与数据边界先规划，不提前实装。

## 5. 玩家核心路径

`打开 → 进入大厅 → 选择游戏 → 选一二/布布 → 游戏关卡/无尽 → 结算与奖励 → 继续/返回大厅`。

未来新增：`好友一起玩 → 选游戏/创建房间 → 主动分享邀请 → 好友加入 → 两人选角/准备 → 游戏中 → 结算/继续/换游戏`。

## 6. 公共成长机制

- 饼干币主要兑换装扮、家具、表情等**非必需奖励**；塔防防御升级/黄金矿工具升级属于各自游戏的内部进度。
- 玩家**不需靠刷其他小游戏**才能解锁主游戏关键内容；没有付费设计前，不预设内购或强制广告策略。
- 存档分层：玩家档案、公共奖励、每游戏独立进度；必要时支持迁移版本。

## 7. 初期成功判断（指标定义，数值须测试后确定）

关注首次 3 分钟退出、关卡完成/失败分布、同游戏复玩、次日/7 日留存、游戏切换、低端手机性能、崩溃率。当前没有可用玩家数据，**不得把目标臆定为已验证结果**。

## 8. 待确定事项

- 一二布布角色在游戏中商业使用的授权范围、正式原始美术参考与命名使用范围。
- 不同宽高比、安全区和触控布局的具体适配；后续双人横版冒险的玩法体验单独立项，保持全项目横屏方向。
- 用户画像、首发运营方案、正式头像和配色、微信 AppID、服务器地区与隐私方案。
- 软著、小游戏审核、备案、广告与商业化作为**提审前独立合规工作**，不阻挡占位素材的本地原型。
