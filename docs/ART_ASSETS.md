# 美术、动画、UI 与音频资源规范

> DOC-ART · v1.8 · 2026-10-29 · 规格为**原型建议**，样板验证后固定正式导出参数。功能原型优先，正式真实角色目标及发布前授权门槛不变。

## 1. 角色规范


- 一二：小白熊；布布：小棕熊。正式形象必须以**原作者黄小B确认的原作版本**和获准使用的原始素材为标准；不得另设计相似熊、把几何占位当正式角色或用 AI 近似图代替原作。
- 五官、耳朵、腮红、身体比例、轮廓和动作不得凭想象补画或修改。缺失视角/遮挡部分/动作原稿先向作者索取；现有占位只保留既有工程测试用途，本次不改选角源码。
- 两个角色拥有同等完备度的三视图/颜色/比例说明、表情、基础移动与互动动画、选择头像和游戏专属动作。
- 原型首批：正面/侧面/背面 + 待机、移动、受击/反馈、胜利、失败 + 6 种表情；动画帧数与像素尺寸由 P1/P2 真机样板验证决定，不现在虚构像素规范。
- 角色差异是玩法设计，不得把一二固定为 NPC 或默认取消一二操控。

## 2. 建议原始与导出格式

- 保留可编辑原稿（PSD/KRA/ASE 等）与导出的透明 PNG；短音效建议使用可经引擎验证的常用格式并留原始制作文件。
- 精灵以统一原点/锚点/朝向导出；图集、压缩及纹理由目标真机测量决定。
- 约定基础命名示例：`yier_idle_01.png`、`bubu_win_03.png`、`ui_btn_primary.png`、`gold_rock_small.png`、`sfx_coin_pickup.wav`。
- 引擎碰撞体与视觉偏移分离，换动画不应改玩家移动/碰撞逻辑。

## 3. 资产分类与阶段优先级

| 类别 | 原型阶段 | 首发阶段 |
| --- | --- | --- |
| 双角色 | 同规格占位图、两种头像、必要动作 | 全基础动画与表情、对应关卡互动 |
| 大厅 UI | 游戏入口、开始、返回、设置 | 布布小屋、图鉴与成就 |
| 塔防 | 1 个场景、最少 2 种防御/敌人做机制验证 | 章节场景、6 类敌人/防御（具体数量需平衡验收） |
| 黄金矿工 | 抓钩、矿物、计分、基本背景 | 不同矿洞、升级、障碍、结算表现 |
| 合成/贪吃蛇 | 替代图块、棋盘、简单音效 | 图鉴/地图/排行榜或个人纪录 |
| 音频 | 简单原创/合规占位短音效 | 分游戏配乐、交互音效、音量控制 |

## 4. 素材来源与权属

P1-02 大厅使用 `LobbyView.ts` 的原创程序几何头像/面板：两角色都在 136×136 **设计单位**容器内，由同一绘制函数的圆/椭圆构成，一二暖白 `#FFF9EF`、布布棕 `#B67B55`，名称/身份用相同字号。随 1280×720 大厅等比缩放；这不是 PNG 导出像素规范，也不冒充正式 IP 立绘或动作。没有下载图片、字体、音乐/音效，字体使用引擎系统字体，具体字形与可读性待 Windows/真机验证。来源登记见 ASSET_LICENSES。

每个**进入正式资源目录**的第三方/原创素材都登记于 `ASSET_LICENSES.md`，记录文件路径、作者/来源、使用方式、商业授权范围、证据地址、是否改编及审核日期。没有明确来源或授权的资源**不得作为正式发布素材**。

P1-03 选角复用同一 `bear()` 几何绘制方法及唯一 CHARACTERS 数据，没有新增图片/字体/音频。左右角色卡均 360×292，内部头像容器仍 136×136 设计单位，姓名/身份/选中状态字号一致；「已选/已确认」文字和底色表示选择，边框另表示键盘焦点。后续 16:9 真实运行发现未选卡片与白熊同色，双方卡片统一改为 #EEE4D4，保留几何占位不导入正式素材；修复前后原图见 [GUI 证据报告](reports/2026-10-28_issue-3_windows-gui-acceptance.md)。本次真实编辑器补验 4:3/21:9，双卡/中文/状态/按钮完整，分别上下/左右留黑，见 [GUI 完成报告](reports/2026-10-28_issue-3_windows-gui-completion.md)。真机触控/安全区仍未测，不由桌面设备预设推定通过。

原游戏的商标、角色图像、关卡数据、音乐、截图不得直接搬运。经典规则可研究，但应做原创关卡、道具、美术、音乐与互动机制。

P1-04 将原 bear() 几何抽到 CharacterVisual.ts 的共享创建接口，所有角色显示使用同一身份目录/136×136 容器与原形状；操作场新增的是原创目标/面板。没有下载、加工或设计正式角色图。新模块沿用 1280×720 等比完整显示，真实画面/替换尚未验收，见 [开发报告](reports/2026-10-29_issue-4_game-lifecycle.md)。原来源研究及后续制作建议保留。

## 5. 文件生命周期

- `prototype` 占位素材和 `release` 正式素材明确区分，不把网络搜索得到的示意图直接导入正式包。
- 删除素材前查找引用和 `.meta`，不能随手清理 Cocos 元数据造成 UUID 断链。
- 每次素材替换要做可视化验证（Windows）与资源完整性检查（Mac CLI 可做静态部分）。
