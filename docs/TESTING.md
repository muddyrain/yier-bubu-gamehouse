# 验证分层、证据与发布质量门槛

> DOC-TEST · v1.0 · 2026-10-26 · 测试脚本尚未建立，不代表任何游戏已通过。

## 1. 分层测试

| 层 | 检查目标 | macOS 默认 | Windows |
| --- | --- | --- | --- |
| T0 文档和静态资源 | 链接、编号、素材登记、配置数据 | 允许纯 CLI | 允许 |
| T1 纯逻辑单测 | 计分、碰撞判定、关卡条件、存档迁移 | 允许无 GUI CLI，先审脚本 | 允许 |
| T2 TypeScript 检查 | 类型、Lint、入口契约 | 允许无 GUI CLI，先审脚本 | 允许 |
| T3 引擎场景测试 | 加载/卸载、动画、音频、内存、触控 | **默认禁止** | 允许 Cocos/模拟器 |
| T4 微信真机 | 包体、手机触控、启动、后台恢复、性能 | **默认禁止 GUI 启动** | 允许微信工具与真机 |
| T5 双人联机 | 两机两账号、分享、WSS、重连、结算 | 仅纯服务端逻辑部分 | 允许完整联调 |

## 2. 环境与真实性约束

- 每次报告区分 **macOS CLI passed、Windows GUI passed、微信真机 passed**，不能互相替代。
- 用户未授权 Mac GUI 测试，不得因为想完善报告就打开 Cocos、微信工具或浏览器。
- 编译通过不能等同操作手感通过、场景绘制通过或游戏已上线。
- 测试时间、机器和脚本必须真实；禁止臆造帧率、内存、关卡通过率、链接或截图。

## 3. 初始功能验收门槛

- 大厅：四款游戏入口占位或已实现入口区分准确，返回不会残留音频/定时器。
- 角色：一二白熊、布布棕熊，选角结果进入游戏，无默认布布绑定。
- 存档：退出和重新启动可恢复已保存进度，旧 schemaVersion 可迁移或清楚拒绝。
- 主游戏：前 5 关可顺序完成，失败和胜利均可重试；关卡配置而非写死。
- 经典游戏：完整开始-操作-结算-重玩的循环。
- 多人：P5 才作验收，不因接口存在就视为上线。

## 4. 报告最少字段

| 字段 | 示例（仅格式，不是真实测试） |
| --- | --- |
| OS/环境 | `macOS 15.x / Windows 11` |
| 操作 | `typecheck`, `Windows Cocos scene run` |
| 真实命令或步骤 | 记录实际执行的准确命令/操作 |
| 结果 | `passed / failed / not_run / blocked` |
| 输出/证据 | `.local/validation/<task>/...` / Windows 真机记录 |
| 风险 | 视觉/性能未验证、资源授权待确认 |

## 5. 日志与进程管理

- 日志写在项目下 `.local/validation/<task-id>/`，默认不提交；必要证据复制到经过授权的报告位置。
- Mac CLI 测试有时限、非常驻、结束后确认自身子进程退出；不能凭一个未退出的后台命令称通过。
- Windows GUI 测试结束关闭自己启动的调试进程和模拟器，不干预无关窗口。

## 6. 性能与发布

FPS、首包体积、加载耗时、首局时长、崩溃率、低端手机机型应在 P2/P4 **实测后**固定阈值。微信小游戏具体分包与上架政策上线前按官方最新规则重新核实。
